[[v1.1]]
== Bonita Process Designer 1.1

Released on September 28, 2026.

{productName} 1.1 lets you organize processes in folders and in a process tree, open called processes in document tabs, export a process together with the processes filed under it, and import a Bonita Studio file even when it contains an element the editor cannot build. It also closes several security and privacy gaps, and makes an installation easier to diagnose.

[discrete]
=== Highlights

* *Folders* — a folder holds processes and other folders. It is not a process itself, and like a diagram it belongs to a group. You create, rename, move and delete folders from the home page. Clicking a folder opens it: the page shows one level at a time, with a breadcrumb back to the top. The address bar carries the folder path by name (for example `/home/f/Finance/Onboarding`), so you can bookmark a folder, share its link or open it in a new tab. The top level is called *Home*. Two folders at the same level cannot have the same name, whatever the case.
* *Filing and moving* — a process is filed in at most one place: in a folder, or under another process, which builds the process tree shown on the home page. Each diagram card shows where the diagram is filed, and its menu has a *Move to…* action. You can select several processes and move them at once, by drag and drop, or with the *M* key in the process tree, and undo the move. When only some of them can move, the result says which ones did not.
* *Duplicate titles* — two processes can now have the same title, for example a "Validation" process under HR and another under Finance.
* *Called processes and document tabs* — a Call Activity can reference another diagram. Opening the called process from the Call Activity opens it in a document tab inside the application. The calling diagram keeps its zoom, selection and scroll position, and you return to it in one click. A Call Activity that would make a process call itself, directly or through other processes, cannot be saved. Deleting a process shows which diagrams call it. The reference survives a BPMN export and import, in the form Bonita Studio resolves.
* *Search with filing paths* — each search result shows where the diagram is filed. Selecting a segment of that path opens that level. A *My processes* filter narrows the results to the diagrams you created, and combines with the group and label filters.
* *Export a process and the processes filed under it* — you can export a process together with the processes filed under it, as a single BPMN file. The export is limited in depth and in number of diagrams. It is checked beforehand for elements Bonita Studio cannot receive, and when it is refused you are offered to export the diagram alone. An exported file also records where the diagram was filed: importing it files the diagram again under the same parent when that parent exists, and at the top level otherwise.
* *Partial import* — a `.bpmn` file that contains an element the editor cannot build, such as the actor participant that Bonita Studio 11 adds to every new diagram, now imports everything else and reports what was skipped. Before, the whole file was rejected.
* *Pools named in Bonita Studio* — an exported process now carries the name of its Pool. Before, every Pool reached Bonita Studio labeled with an identifier.
* *Escape stops a simulation* — pressing *Esc* stops a running simulation at any moment, during the animation as well as while a gateway or start prompt is open.
* *A Save is reported only once it is stored* — the editor reports a Save as successful, and stops flagging unsaved changes, only after the server has confirmed the write. A failed Save keeps the changes flagged, so the warning shown when you leave the page still protects them, and a server error shows a Support ID. A Save requested while an autosave is running waits for that autosave and reports its result.
* *Password rule shown* — the minimum password length (6 characters) is shown on the registration form, on the password change required at first login, and on the user form of the Admin pages.
* *AI Modify and Analyze as background jobs* — like generation, *Modify* and *Analyze* now run as background jobs, so a slow AI provider no longer holds the server for the whole call. An AI failure shows a Support ID that you can copy.
* *Easier diagnosis* — an Admin can download a diagnostic archive from the *Admin* pages: version, license status (never the license file itself), health and database connectivity, deployment mode, a filtered view of the configuration, the end of the log and recent AI jobs, all as plain text or JSON. It works even while the license is invalid. The Admin pages also show the *Installation ID*, which identifies your instance to Support. The standalone distribution writes its own rotating log file, `logs/process-designer.log`, next to `app.jar`, and an Admin can change a log level on a running instance without restarting it. See xref:ROOT:get-support.adoc[Get support] and xref:administration:logging.adoc[Logs and log levels].

[discrete]
=== Other improvements and fixes

* The compensation activity marker, and the shortcut that created a plain intermediate throwing event, are removed from the editor, because Bonita Studio cannot receive either. Importing a file that uses the marker reports that it was dropped.
* Exported PNG images, prints and home-page thumbnails no longer include the selection outline or the elements highlighted by a simulation.
* The *Import Logs* panel is no longer empty after an import in single-JAR deployments.
* Marking an import log entry now works when the editor and the API are served from different origins.
* *Shift+Arrow* extends the selection in the process tree.
* Under heavy collaborative editing, rate-limit warnings are grouped into one message instead of a cascade of notifications.
* Warning text meets the WCAG AA contrast ratio.
* The Docker image has an explicit memory ceiling (`-Xmx192m`), as does the standalone runnable (`-Xmx512m`). Override it with `JAVA_OPTS`.
* The `docker-compose.yml` shipped in the archive caps the size of container logs: 500 MB for the application, 30 MB for each other service.

[discrete]
=== Behavior changes

* *Deleting a folder moves its contents to Home.* The processes and sub-folders directly inside a deleted folder move to the top level (*Home*), whatever the depth of the deleted folder, not to the level above it. No process is deleted with the folder. A sub-folder whose name is already taken at the top level is renamed `Name (2)`, `Name (3)`, and so on. Deleting a process that has processes filed under it moves them to the top level in the same way.
* *Save during real-time editing.* While the editor is connected for real-time editing, an explicit Save no longer sends the whole document, which could overwrite a co-editor's changes. The server saves the live document immediately instead, and creates a version as a Save did before, at the same frequency (`AUTO_SNAPSHOT_EVERY_N_SAVES`).
* *Diagram titles are no longer unique.*
* *Self-hosted AI service.* AI Modify and Analyze are now background jobs. If `TEXT2BPMN_API_URL` points to your own AI service rather than the default one, that service must support the job API for these two operations.

[discrete]
=== Upgrade notes

Before you upgrade:

. *Back up the database.* The database migrations of 1.1 cannot be rolled back: returning to 1.0 means restoring this backup. For the Docker distribution, see xref:installation:docker-installation.adoc#_back_up_and_restore_the_database[Back up and restore the database].
. *Install a valid license file.* The `LICENSE_BYPASS` variable no longer exists, and license enforcement cannot be turned off. An installation that ran with `LICENSE_BYPASS=true` refuses every request except sign-in and the license page until a valid `.lic` file is installed. See xref:administration:license-management.adoc[Manage the license].
. *Docker distribution: use the `docker-compose.yml` of the 1.1 archive.* It references the 1.1 image. If you edited the 1.0 file, carry your changes over. The volume names do not change, so your data, license file and TLS certificate are kept. If you ship container logs to your own aggregator, override the new `logging:` settings.
. *Standalone distribution: do not redirect the console into `logs/`* (for example `./start.sh > logs/app.log`). The application now writes its own rotated file there. Copy your `config.env` over: `config.env.example` documents the new optional variables.

*Database migrations.* Migrations `V21` to `V28` run automatically at the first start of 1.1, with no manual step. They add folders and filing, Call Activity references between diagrams, and length limits on import log fields, and they remove the uniqueness of diagram titles. Once two diagrams share a title, this database can no longer be restored into a 1.0 installation.

*Check before you upgrade.* Migration `V26` adds length limits (255, 255 and 2,000 characters) to the import log table, and PostgreSQL checks them against the rows already there. If an existing row exceeds a limit, the migration fails and the application does not start. This is not expected with import logs written by the editor, but you can check beforehand:

[source,sql]
----
SELECT count(*) FROM migration_entries
 WHERE char_length(element_id) > 255
    OR char_length(original_type) > 255
    OR char_length(reason) > 2000;
----

A count other than zero must be dealt with before the upgrade, for example by deleting those import log rows.

*Version reporting.* 1.1 is the first release whose `/actuator/info` endpoint, diagnostic archive and page footer report the release version. Versions 1.0.0 to 1.0.2 report `1.0.0-SNAPSHOT` on the back end and `1.0.0` in the footer.

[discrete]
=== Security and privacy

* *No user-authored text in product analytics.* Product analytics (PostHog) is off by default. When it is enabled, it no longer receives AI prompts or excerpts, AI error messages, diagram titles, folder names, search terms or user names. Events keep counts, identifiers and the user's role, plus the company name of the installation. Automatic capture, session replay, heatmaps, surveys and feature flags are turned off. The names previously stored on existing analytics user profiles are removed.
* *Same-origin redirects only.* After sign-in, the application only follows a redirect to a page of the application itself, and falls back to Home otherwise. Before, a crafted link could send a user to another site after sign-in.
* *Same-origin framing only.* Every page forbids being embedded in a frame by another site (`X-Frame-Options: SAMEORIGIN` and `Content-Security-Policy: frame-ancestors 'self'`). Same-origin framing stays allowed, because the document tabs use it.
* *License details for Admins only.* The customer name, license type, expiry date, host name and operating system of the license are now returned to Admins only.
* *Group isolation of import logs.* A Creator can no longer read or change the import log of a diagram in another group.
* *Nothing sensitive in the logs.* At the default log level, the logs no longer record a process title quoted in a database error, part of a malformed request, the session cookie of a rejected request, proxy credentials, or the initial admin password.
* *Admin-only management endpoints.* `/actuator/info`, `/actuator/health` and `/actuator/loggers` are reserved to Admins.
* *Updated dependencies.* Spring Boot 3.5.16 (embedded Tomcat 10.1.55), and patched front-end dependencies.

[discrete]
=== Known issues

* *Exported BPMN files declare `exporterVersion="1.0.0"`.* This value is fixed in the editor and does not follow the application version: do not use it to tell which release produced a file. Importing these files is not affected.
* *A dropped connection can go unnoticed during real-time editing.* Heartbeats are disabled on the real-time connection, so a connection that died without closing (a laptop waking from sleep, a Wi-Fi drop) still looks connected. Edits made over it are lost, and a Save can still report success. After a network interruption, reload the diagram and check that your latest changes are there.
* *The editor's source map is served without authentication.* `/bpmn-editor-bundle/bundle.js.map` can be downloaded before sign-in and exposes the editor's client-side source code. It contains no diagram or user data. If this is a concern, block that path on your reverse proxy.

[[v1.0]]
== Bonita Process Designer 1.0

The first release of {productName}, a web-based BPMN 2.0 diagram editor for designing business processes and exporting them to Bonita Studio.

[discrete]
=== Highlights

* *Visual BPMN editor* — create and edit BPMN 2.0 diagrams on a drag-and-drop canvas, with a palette of supported elements, connections (sequence flows, including conditional and default flows), pools and lanes, an inspector panel for element properties, undo/redo, and zoom, pan and fit controls. See xref:user-guide:editing-diagrams.adoc[Edit a diagram].
* *AI diagram generation* — generate a diagram from a natural-language description, then modify or analyze it. Generation runs as a background job with a phased progress indicator and is subject to a per-group quota. See xref:user-guide:ai-generation.adoc[AI diagram generation].
* *Real-time collaboration* — several people can edit the same diagram at once, with live presence and an authoritative server-side store that keeps everyone in sync. See xref:user-guide:real-time-collaboration.adoc[Collaborate in real time].
* *Roles, groups and data isolation* — three roles (Admin, Creator, Reader) scoped to groups, so users only see the diagrams in the groups they belong to. See xref:administration:permissions-and-roles.adoc[Roles and permissions].
* *Comments and labels* — discuss a diagram in a per-diagram comment thread, and organize and filter diagrams with labels. See xref:user-guide:comments.adoc[Comment on diagrams] and xref:user-guide:labels.adoc[Organize diagrams with labels].
* *Marketplace connectors* — browse a connector marketplace and attach connectors and actor filters to elements. The bindings are written into the exported BPMN file (Bonita Studio currently ignores them on import, so you reconfigure them there). See xref:user-guide:marketplace-connectors.adoc[Use marketplace connectors].
* *Diagram versioning* — edit a private draft and publish immutable snapshots that your group can view and restore. See xref:user-guide:diagram-versioning.adoc[Version your diagrams].
* *Process simulation* — run a token through a diagram to visualise the flow and check gateway paths. See xref:user-guide:process-simulation.adoc[Simulate a process].
* *Export and import* — export diagrams to BPMN 2.0 XML (compatible with Bonita Studio), PNG, and JSON, and import BPMN XML or JSON, with automatic migration of unsupported elements. See xref:user-guide:export-and-import.adoc[Export and import diagrams].
* *Flexible deployment* — install with Docker Compose, as a standalone bundle, or in Bonita Runtime mode. See xref:installation:installation.adoc[Installation].
* *Diagnosable logs* — every log line of a request carries a correlation id, and the same id is shown to the user as a *Support ID* when a server error occurs, so a user's report maps straight onto the server logs. See xref:administration:logging.adoc[Logs and log levels].
